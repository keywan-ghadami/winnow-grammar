# ADR 14: Shared Context Pattern for String Interning

**Status:** Proposed. Carried over from the syn-grammar monorepo at the fork
point (`64be1ef`, 2026-08-31) — it only ever concerned `winnow-grammar` there.
The number comes from the ADR series of the original repository; it had
previously been filed as "ADR-11" there, a number that was assigned twice.

**Date:** 2024-03-15

## 1. Context and problem

To improve performance and memory efficiency, a string-interning mechanism for
parsing identifiers is introduced, available through the `ident` primitive of
the grammar DSL.

The central architectural challenge is that the `InternerContext` (the data
structure that does the interning) is not a temporary implementation detail of
the parser. In a compiler toolchain the interner is a long-lived, central data
structure that must outlive a single parse and be shared across several source
files (potentially in parallel). The parsing framework needs a robust and
explicit way to reach this user-managed, shared context.

## 2. The decision: the "Shared Context Pattern"

We introduce an explicit "Shared Context Pattern". Responsibility for creating
the `InternerContext` and managing its lifetime lies entirely with the user of
the framework. The parser reaches that context through a well-defined
structure.

1.  **Public `ParseContext` struct:** The framework provides a new, public,
    generic struct.

    ```rust
    // In `winnow-grammar/src/lib.rs`
    pub struct ParseContext<S = ()> {
        pub interner: std::sync::Arc<InternerContext>,
        pub user_state: S,
    }
    ```

2.  **Unconditional use in the stream state:** All parsers generated by the
    `grammar!` macro **always and without exception** use the state type
    `winnow::Stateful<&'a str, ParseContext<S>>`. There is no conditional code
    generation.

3.  **"Outside-in" user workflow:** The library user controls the context:
    a. The user instantiates the `InternerContext` once for the whole
       compilation.
    b. They wrap it in a `std::sync::Arc`.
    c. For each parse (e.g. for each file) a `ParseContext` is created with a
       clone of the `Arc` and handed to the parser.
    d. This enables stateless, high-performance, thread-safe parsing across
       several files.

## 3. Implementation details

### 3.1. Core data structures (`winnow-grammar/src/lib.rs`)

The following structures are defined in the main library file:

```rust
// In winnow-grammar/src/lib.rs

use std::sync::Arc;
use lasso::{ThreadedRodeo, Spur};

pub type Symbol = Spur;
// IMPORTANT: ThreadedRodeo instead of Rodeo!
pub type InternerContext = ThreadedRodeo;

pub struct ParseContext<S = ()> {
    // NO Mutex! ThreadedRodeo is already thread-safe internally.
    pub interner: Arc<InternerContext>,
    pub user_state: S,
}

impl<S: Default> Default for ParseContext<S> {
    fn default() -> Self {
        Self {
            interner: Arc::new(InternerContext::new()),
            user_state: S::default(),
        }
    }
}

/// The input stream type for all parsers generated by the macro.
pub type ParseInput<'a, S = ()> = winnow::Stateful<&'a str, ParseContext<S>>;
```

### 3.2. Macro code generation (`winnow-grammar-macros/`)

The macro logic is simplified, since conditional trait bounds are no longer
needed.

1.  **`codegen/rule.rs`**: The signatures of the generated parser functions
    (`parse_<rule_name>`) are unified.

    ```rust
    // Generated signature in codegen/rule.rs
    pub fn parse_<rule_name><'a, S>(...) -> impl Parser<
        ::winnow_grammar::ParseInput<'a, S>, // now an alias for Stateful<..., ParseContext<S>>
        ...,
        ...
    >
    where
        S: 'a + Clone + std::fmt::Debug,
    { ... }
    ```

2.  **`codegen/expr.rs`**: Handling of the `ident` primitive reaches the
    interner directly, without any locking.

    ```rust
    // Generated code for `i:ident` in codegen/expr.rs
    let s: &str = // ... code that parses the identifier string ...
    let symbol = input.state_mut().interner.get_or_intern(s);
    Ok(symbol)
    ```

### 3.3. User workflow (example)

The end user's code stays explicit and simple:

```rust
use std::sync::Arc;
use winnow_grammar::{ParseContext, InternerContext};

fn main() {
    let input_str = "my_identifier";

    // 1. The user creates and manages the shared, thread-safe interner
    let interner = Arc::new(InternerContext::new());

    // 2. The user creates the ParseContext
    let mut context = ParseContext {
        interner: interner.clone(),
        user_state: (),
    };

    // 3. The parser runs with explicit state
    let input = winnow::Stateful::new(input_str, context);
    // ...
}
```

### 3.4. Test harness (`winnow-grammar/src/testing.rs`)

The test helpers are adapted to manage the `ParseContext` and expose it to
assertions, which makes validating `Symbol` values possible.

```rust
// `assert_success_with` is adapted to pass the context to the closure
impl<'a, O> TestResult<'a, O> {
    pub fn assert_success_with<F>(self, check: F)
    where
        // The closure now receives the result AND the final state (incl. interner)
        F: FnOnce(O, &ParseContext),
    {
        // ...
        check(output, &final_state);
        // ...
    }
}
```

## 4. Consequences

### Positive

*   **Correct architectural alignment:** The interner's lifetime is managed by
    the application, where it belongs.
*   **Fast, thread-safe sharing:** Using `Arc<ThreadedRodeo>` enables
    lock-free, high-performance parallel parsing into the same interner, which
    is essential for multi-core compilers.
*   **Reduced macro complexity:** Code generation is radically simpler, since
    no conditional analysis or trait bounds are needed.
*   **Excellent testability:** Unit tests can create the `ParseContext`
    explicitly and inspect the `interner` after parsing to validate `Symbol`
    ids.

### Negative

*   **Explicit setup by the user:** Users must always create a `ParseContext`,
    even if their grammar never uses the `ident` primitive. This is a small but
    necessary explicit step that secures the correct architecture.

## 5. Rejected alternatives

### Alternative A: encapsulated `InternalParseState`
*   **Reason for rejection:** Architecturally wrong, since the interner must
    outlive the parser and be shared.

### Alternative B: conditional generation of trait bounds
*   **Reason for rejection:** Needless complication of the macro and a leaky
    abstraction.

### Alternative C: `Arc<Mutex<Rodeo>>`
*   **Reason for rejection:** The `Mutex` creates lock contention, which
    destroys throughput when parsing in parallel. Using the natively concurrent
    `ThreadedRodeo` is clearly superior.
